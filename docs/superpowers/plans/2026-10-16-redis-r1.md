# Redis R1（浏览与查看）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 datavim 里连上 Redis（单机，密码可选，可走 SSH 隧道）；树里浏览 db 和按分隔符分组的 key；按模式过滤，或者直接按名字打开 key；在 Key 详情页里只读查看六种类型的值。整个 R1 不执行任何写命令。

**Architecture:** 新建 `internal/rdb`，用 go-redis v9 封装 Redis 连接（地位相当于 `internal/db`），新建纯包 `internal/rcmd`，负责 key 名转义和模式处理。`session.Manager` 用 `connKey{conn, db}` 缓存 `rdb.Client`，密码、隧道、Reset 走现有逻辑。UI 层的树增加 Redis 节点类型；SCAN 分批扫描的状态（`keyScan`）放在 `ui.Model` 里，每批结果到达后重建 db 节点下的分组子树。Key 详情页是一种新的 tab：String 用文本视图，集合类型复用 `panes/grid`。

**Tech Stack:** Go 1.26、`github.com/redis/go-redis/v9`、`github.com/testcontainers/testcontainers-go/modules/redis`（v0.44.0，和现有 testcontainers 同版本）。

**Spec:** `docs/superpowers/specs/2026-10-16-redis-design.md`（本计划只覆盖 §3 和 §4 的 R1 部分，§3.4 的配置也包含在内）

## Global Constraints

- 驱动名是 `redis`，默认端口 `6379`。`database` 字段是 db 编号，留空表示 `0`，必须是非负整数。
- `params`：`separator`（默认 `:`）、`tls = "true"`、`tls_skip_verify = "true"`。
- 主要目标是 Redis 6.0+，5.x 也要能用；低于 5.0 不保证。RESP3 握手失败时退回 RESP2。
- key 名和值一律原样传递（Go `string` 当字节串用），转义只在显示时进行。节点和 tab 都保存原始 key。
- R1 不发送任何写命令（只用 `PING`、`INFO`、`CONFIG GET`、`DBSIZE`、`SCAN`、`TYPE`、`PTTL`、长度类命令、`OBJECT ENCODING`、`MEMORY USAGE`、`GETRANGE`、`HSCAN`、`LRANGE`、`SSCAN`、`ZRANGE`、`XRANGE`、`AUTH`、`SELECT`、`HELLO`）。
- 扫描默认值（spec §4.1、§4.2）：每批 `COUNT 1000`；不过滤时每次加载最多扫描 10,000 个；过滤时找到 500 个匹配或扫描满 100,000 个就停；一个 db 子树最多保留 100,000 个 key；prod 连接每批之间停 10 ms。
- 大 String：`STRLEN` 超过 1 MB（1,048,576 字节）只读前 1 MB，并提示 `showing first 1 MB of N`。
- UI 文字用英文；按键名一律用 `keyHint` 生成，不写死；新按键放进 `keymap/defaults.go` 并带描述。
- 不记录、不显示密码（日志里也不能出现）。
- Redis 连接上触发 SQL 专属功能（控制台、结构、对比、导入、全局搜索的 catalog、事务开关、节点菜单里的表操作）时，提示 `not supported for redis yet`，然后直接返回，不能报错或卡住。
- 提交信息用 Conventional Commits 并带 scope，**不加 Co-Authored-By**。每个用户能看到的改动都在 `CHANGELOG.md` 的 `[Unreleased]` 下加一行（Task 10 统一写）。

## Review Focus

1. **二进制 key 名**：key 是 `"\x1f\x8bab\xff"` 时，树显示 `\x1F\x8Bab\xFF`，打开详情页用的是原始字节，`TYPE` 能查到；复制名字时得到 redis-cli 能直接用的 `"\x1f\x8bab\xff"`。测试在 Task 2（Escape/Quote）和 Task 4（集成测试的往返）。
2. **扫描时 key 过期或被删**：SCAN 返回的 key 在 `TYPE` 时已经不存在（返回 `none`），这样的 key 不能出现在树里，也不能报错。测试在 Task 3。
3. **没设密码的 Redis**：钥匙串里没有密码时直接连，不弹密码框；服务器回 `NOAUTH` 才弹。测试在 Task 5。
4. **扫描中途刷新或改过滤**：旧扫描的批次晚到时必须丢弃，不能混进新结果。测试在 Task 7（generation）。
5. **详情页打开后 key 过期**：刷新时显示 `key no longer exists`，不报错，翻页动作不再发请求。测试在 Task 9。
