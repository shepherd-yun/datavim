# Kafka K2（Schema Registry 与进阶运维）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 K1（v2.4.0）基础上：修改 topic 配置、增加 partition；删除消息（DeleteRecords）、删除 group、删除 group 在 topic 上的 offset；Schema Registry（树、Schema 标签页、Avro / Protobuf / JSON Schema 解码和序列化、注册版本、改兼容级别、软删除版本）；把消息复制到 producer console 重发、从 JSONL 文件批量发送；消费隔离级别开关；`params.broker_map`；OAuth 和 AWS MSK IAM 认证。

**Architecture:** `internal/kafka` 给 `Client` 加 5 个写方法，新增 `Registry`（包装 franz-go 的 `pkg/sr`，HTTP 也走 `Config.Dial`，即 SSH 隧道）。`session` 的 `guardedKafka` 覆盖新写方法，新增 `guardedRegistry`，两者都由反射测试保证没有漏掉的写方法；连接密码以外的秘密（Schema Registry 密码、OAuth client secret）用 `SecretRequiredError` 在第一次需要时询问。`kmsgx` 增加写操作分级、配置修改计划、删除消息计划、Confluent 线格式和三种 schema 的编解码、草稿的二进制和 schema 头、记录 → 草稿、JSONL → 草稿。UI 增加 KafkaConfig 和 KafkaSchema 两个 keymap 上下文、树的 Schema Registry 节点、Schema 标签页，所有 K2 写操作都经过一个 `kafkaConfirm` 帮助函数按 §8.2 确认。

**Tech Stack:** Go 1.26、`github.com/twmb/franz-go`（已有：`kgo`、`kadm`、`kfake`、`sasl/oauth`、`sasl/aws`），新依赖：`github.com/twmb/franz-go/pkg/sr`（含 `sr/srfake`）、`github.com/hamba/avro/v2`、`github.com/bufbuild/protocompile`、`google.golang.org/protobuf`（`dynamicpb`、`protojson`）、`golang.org/x/oauth2/clientcredentials`、`github.com/aws/aws-sdk-go-v2/config`。版本用 `go get <mod>@latest` 时的最新稳定版。**实现前用 Context7（`/twmb/franz-go`）确认 `sr.Client` 的确切方法名和签名**（`SchemaByID`、`Subjects`、`SubjectVersions`、`SchemaByVersion`、`CreateSchema`、`Compatible`、`Compatibility`、`SetCompatibility`、`DeleteSchema` + `SoftDelete`），本计划只规定 sqlvim 自己的接口。

**Spec:** `docs/superpowers/specs/2026-10-20-kafka-design.md`（本计划覆盖 K2：§7，以及 §3.4 / §8 里标了 K2 的部分）。K1 计划：`docs/superpowers/plans/2026-10-20-kafka-k1.md`。

## Global Constraints

- 只读连接拒绝所有写和危险操作，提示是现有的 `readOnlyHint` / `session.ErrReadOnly`。
- 写操作分级（spec §8.1）：**写** = 修改 topic 配置、增加 partition、注册 schema、修改兼容级别（以及 K1 的发消息、建 topic、重置 offset）；**危险** = 删除消息（DeleteRecords）、删除 group、删除 group 的 offset、软删除 schema 版本（以及 K1 的删 topic）。
- 确认（spec §8.2）：危险操作在任何连接上都要输入对象名（topic 名 / group 名 / subject 名）；prod 写操作按 `y`；prod 重置 offset 输入 group 名；非 prod 发消息不确认，其他写操作按 `y`；批量发消息先解析全部，再确认一次，确认框写明条数。
- 所有写方法只通过 `session` 里的包装类型检查只读（spec §8.3），反射测试要在接口新增写方法却没加检查时失败。
- 修改配置用增量修改（`kadm.AlterTopicConfigs`，`SetConfig` / `DeleteConfig`），**只提交改动的项**。
- 删除 group、删除 group 的 offset 都要求 group 是 Empty（删 offset 还允许 group 不再订阅这个 topic），客户端在请求前重新读状态，不信任 UI 的旧状态。
- Schema Registry：兼容 Confluent API；解码失败或 schema 取不到时，这条消息按 hex 显示并在旁边显示错误，不影响其他消息；不做硬删除。
- Schema Registry 线格式：第 1 字节 `0x00`，后 4 字节大端 schema id；Protobuf 之后是 message index 数组（Confluent 的 zigzag varint 编码，只有 `[0]` 时写成单个 `0`）。
- 秘密：SASL 密码仍是连接密码（钥匙串账户 `<连接名>`）；Schema Registry 密码是 `<连接名>#schema-registry`，OAuth client secret 是 `<连接名>#oauth`（`secret.EnvVar` 因此是 `SQLVIM_PASSWORD_<名字>_SCHEMA_REGISTRY` / `_OAUTH`）。密码、token、client secret、URL 里的 userinfo 不写日志、不显示。
- **所有网络连接都走 `Config.Dial`**（broker、Schema Registry 的 HTTP、OAuth 取 token 的 HTTP）；不经过隧道直连是反目标。MSK IAM 取 AWS 凭据走 AWS SDK 自己的凭据链，不经过隧道，sqlvim 不保存 AWS 密钥。
- 消费隔离级别默认 `read_committed`（K1 的 Reader 没设置，用的是 franz-go 默认的 read_uncommitted；这是一个用户可见的变化，写进 CHANGELOG 的 Changed）。
- 默认值：批量发送超过 `1,000` 条时先预览条数和前 5 条再确认（常量 `sendPreviewOver = 1000`，和 K1 的其他默认值一样是常量）；Schema 缓存按连接、按 id，进程内不过期。
- UI 文字用英文；按键名一律用 `keyHint`；新按键进 `keymap/defaults.go` 并带描述；能共用的动作用同一个 Action（spec §6）。
- 提交信息用 Conventional Commits 带 scope（英文，和仓库现有提交一致），**不加 Co-Authored-By**。用户能看到的改动在 Task 22 统一写进 `CHANGELOG.md` 的 `[Unreleased]`。

## Review Focus

1. **Schema Registry 绕过 SSH 隧道**：配了 `ssh` 的连接上，Registry 的 HTTP 请求必须用注入的 `Dial`，否则跳板机后面的 Registry 连不上，或者悄悄直连。测试在 Task 7（计数的 Dial + `srfake`）。
2. **预览后配置被别人改了**：在 Config 部分暂存修改后，另一个人改了同一项；提交时要放弃并提示 `topic configs changed since preview; review again`，其他没改的配置保持原值（不被覆盖成默认值）。测试在 Task 5（kfake）。
3. **看起来像线格式但不是**：value 第一个字节碰巧是 `0x00`、或者 schema id 在 Registry 里不存在；这条显示 hex 和 `schema 7: not found`，同一批里其他消息照常解码，表格不卡。测试在 Task 14。
4. **重发时字节不一致**：value 正文恰好是 `null`（不是 tombstone）、正文里有一行 `===`、key 不是 UTF-8 或带换行、header 值带换行、Schema Registry 线格式的 value；复制到 producer console 再解析后，key / value / header 必须逐字节相同。测试在 Task 9（`FormatDraft` → `ParseDraft` 往返）。
5. **凭据出现在界面上**：`schema_registry_url = "https://u:p@sr:8081"`，或 Registry 返回 401；错误信息、状态栏、日志里不能出现 `p`。测试在 Task 7（错误字符串断言）。
