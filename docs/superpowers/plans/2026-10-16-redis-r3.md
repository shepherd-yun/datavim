# Redis R3（编辑）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Key 详情页里像数据表格一样暂存、提交对 String / Hash / List / Set / ZSet / Stream 的修改，提交前用 `WATCH` 比较旧值、不一致整批放弃；任意 key 可以设 TTL、重命名、删除、新建；树上可以按模式批量删除。只读和 prod 规则对这些 sqlvim 自己生成的命令同样生效。

**Architecture:** 新的纯包 `internal/redit` 把暂存的修改（复用 `edit.Table`）变成一个 `Plan`：要 `WATCH` 的 key、提交前要满足的检查（读命令 + 期望的回复）、在 `MULTI` / `EXEC` 里执行的命令。`rdb.Client.Apply` 在专用连接上执行 `WATCH` → 检查 → `MULTI` / `EXEC`，任何一项不符就返回 `*rdb.ChangedError`。`keyTab` 变成 `stager`，用 `edit.Table` 保存原始字节、给 grid 显示转义后的副本；TTL、重命名、删除、新建、批量删除是不经过暂存的单步操作，都先过 `rcmd.GuardArgs`。

**Tech Stack:** Go 1.26、`github.com/redis/go-redis/v9` v9.23.0（`Client.Watch` / `Tx.TxPipelined`，实现前用 Context7 查当前用法）、testcontainers `modules/redis` v0.44.0（`redis:7` 和 `redis:5`，沿用 `internal/rdb/integration_test.go` 的 `images` / `eachImage`）。

**Spec:** `docs/superpowers/specs/2026-10-16-redis-design.md`（本计划覆盖 §6，以及 §7.2 最后一条"编辑和批量删除同样要过只读和 prod 检查"）

## Global Constraints

- key 名、field、member、值一律用原始字节（Go `string`）传给 `rdb`；`rcmd.Escape` 只用于显示。`edit.Table` 里存的是原始值，grid 显示的是逐格 `rcmd.Escape` 后的副本。
- 编辑手感和数据表格一致，复用同一组 Action 和默认键：`i` / `Enter` 改单元格，`o` 加一行，`dd` 删一行，`u` 撤销一步，`U` 放弃全部，`<Space>w` 提交（先预览命令再确认）。
- 提交规则（spec §6.2）：先 `WATCH key`，执行 `Plan.Checks`；任何一项不符、检查命令报错（比如类型变了）、或 `EXEC` 返回 nil，都整批放弃，提示 `key changed since loaded; refresh and retry`（后面可以接 ` · ` 和原因）。检查全部通过才 `MULTI` / `EXEC`。
- `EXEC` 里某条命令失败时 Redis 不回滚其他命令：提示 `command N of M failed: <错误> · the others were applied`，然后重新加载 key。
- 大 String 只读了前 1 MB（`info.Len > maxStringRead`）时不允许编辑值：`only the first 1 MB was loaded · edit this value in the console`。
- 不是合法 UTF-8 或含控制字符（`hasControl`，tab / 换行 / 回车除外）的值、field、member 不能在编辑器里改：`binary values cannot be edited here · use the console`。删除这样的行是允许的（不经过编辑器）。
- Redis 没有 NULL：编辑器里 `ctrl+n` 存的 NULL、新行留空的格子，在提交时报错 `redis has no NULL · type a value (empty is fine)`。
- 只读连接上所有编辑入口（改格、加行、删行、提交、TTL、重命名、删除 key、新建 key、批量删除）拒绝，提示用现有的 `readOnlyHint`。
- 单步操作（TTL、重命名、新建）在 prod 上按 `y` 确认，非 prod 不确认；删除单个 key 总要确认，非 prod 按 `y`，prod 输入连接名；批量删除同 §6.3（非 prod `y`，prod 输入连接名）。暂存修改的提交总是先预览，prod 的预览标题加 `PROD · `。
- `RENAME` 默认用 `RENAMENX`；目标已存在时弹确认 `<new> already exists · overwrite it?`，确认后才 `RENAME`（prod 上要输入连接名）。
- 删除 key 用 `UNLINK`。批量删除：先 `SCAN MATCH` 数（每批 `COUNT 1000`，prod 每批之间停 `prodScanPause`），预览显示数量和前 20 个 key；确认后重新 `SCAN MATCH`，每批匹配到的 key 按 500 个一组 `UNLINK`；计数和删除都可以用 `Cancel`（`ctrl+c`）停止。常量：`bulkPreview = 20`、`bulkUnlink = 500`，不进 `config.toml`。
- Redis < 6.0（`redit.CapsFor(Client.Version())`）改 String 时不能用 `KEEPTTL`：在 `WATCH` 之后读 `PTTL`，`MULTI` 里 `SET` 后用 `PEXPIRE` 恢复（`PTTL` ≤ 0 时不发）。
- 新按键放进 `keymap/defaults.go` 并带描述；UI 文字里的按键一律用 `keyHint`。UI 文字用英文。不记录、不显示密码。
- 提交信息用 Conventional Commits 并带 scope，**不加 Co-Authored-By**。CHANGELOG 和 README 在 Task 10 统一写。

## Review Focus

1. **`$EDITOR` 加的换行**：用 vim 把 `abc` 改成 `abd` 保存，文件末尾会多一个 `\n`；暂存的值必须是 `abd`。只有原值本来就以 `\n` 结尾时才保留。测试在 Task 6（`TestKeyEditExternalTrailingNewline`）。
2. **二进制值进编辑器**：hash 的 value 是 `"\xff\x00"` 时按 `i` 必须拒绝，而不是把转义文字 `\xFF\x00` 当成新值写回去。测试在 Task 4（`TestKeyEditRefusesBinary`）和 Task 6（String）。
3. **暂存后翻页**：改了第一页的一个 field 后按 `]` 加载下一页，修改还在；`HSCAN` 在第二页又返回了第一页已有的 field 时不显示两次（否则两行各自暂存，会生成两条互相矛盾的 `HSET`）。测试在 Task 4（`TestKeyEditKeepsChangesAcrossPages`、`TestKeyPageDedup`）。
4. **List 里重复的值**：`[a a a]` 一次提交里删掉下标 0 和 2，结果必须是 `[a]`，而不是全删或只删一个。测试在 Task 2（`TestBuildListDelete`）和 Task 3（`TestApplyListDeleteDuplicates`，集成）。
5. **重命名成二进制名字、带暂存修改的标签页**：重命名输入框接受 redis-cli 的引号写法，`"a\xffb"` 必须重命名成原始字节 `a\xffb`；标签页有暂存修改时拒绝重命名和删除；重命名后已打开的标签页跟到新名字（标题、`Key()`、树里的节点）。测试在 Task 7（`TestRenameKeyBinary`、`TestRenameKeyRefusedWithChanges`、`TestRenameKeyRetargetsTab`）。

**Interfaces:**
- Produces:
  ```go
  // Package redit turns staged changes to a Redis key into the commands
  // that apply them and the checks that must hold first (design §6.2). Pure.
  package redit

  type Expect int
  const (
      ExpectValue Expect = iota // a bulk string equal to Value
      ExpectNil                 // nil: the field / member / key is missing
      ExpectInt                 // an integer equal to Int
      ExpectScore               // a score equal to Score (RESP2 string or RESP3 double)
      ExpectLen                 // an array with Int elements
  )
  type Check struct {
      Args   []string
      Expect Expect
      Value  string
      Int    int64
      Score  float64
      What   string // why it failing matters, e.g. `field "a" changed`; shown after " · "
  }
  // Holds reports whether reply v (nil, string, int64, float64, []any, or an error) is what c expects.
  // An error never holds.
  func (c Check) Holds(v any) bool

  type Plan struct {
      Key        string     // WATCHed
      Checks     []Check
      Cmds       [][]string // run in MULTI … EXEC, in order
      RestoreTTL bool       // Redis < 6: PEXPIRE the PTTL read after the checks, after the SET
      N          int        // changes it applies, for the preview's title ("Submit N changes")
  }

  type Target struct {
      Key  string
      Type string // "hash", "list", "set", "zset", "stream"
      Len  int64  // LLEN when the list was loaded
      Tomb string // a list's placeholder for deleted elements; the caller makes it unique
  }
  // Build plans the staged rows of t. Columns by type (keyTab builds them):
  // hash field,value · list index,value · set member · zset rank,member,score · stream id,fields.
  func Build(t *edit.Table, tg Target) (Plan, error)

  var ErrNull = errors.New("redis has no NULL · type a value (empty is fine)")
  ```
  `edit`：
  ```go
  // Append adds rows read from the server after the current ones, keeping staged changes and undo.
  func (t *Table) Append(rows [][]db.Value, ids []string)
  ```
- 规则（Hash / Set / ZSet）：
  - **Hash**：改 value → 检查 `HGET key f` == 原 value，命令 `HSET key f v`；新 field → 检查 `HEXISTS key f` == 0（`What: field "f" already exists`），`HSET`；删除 → 检查 `HGET` == 原 value，`HDEL key f`；改了 field 名 → 检查旧 field 的 `HGET` == 原 value、新 field 的 `HEXISTS` == 0，命令 `HDEL old` + `HSET new v`（v 是这一行当前的 value）。所有 `HDEL` 排在所有 `HSET` 之前。最终 field 名重复时报错 `field "f" appears twice`。新名字正好是这次被删除或改名移走的原 field 时，不加它的 `HEXISTS` 检查（那个 field 的 `HGET` 检查已经在了）；Set、ZSet 同理。
  - **Set**：新 member → `SISMEMBER` == 0，`SADD`；删除 → `SISMEMBER` == 1，`SREM`；改名 → 两个检查，`SREM` + `SADD`。`SREM` 在前。重复时 `member "m" appears twice`。
  - **ZSet**：改 score → `ZSCORE key m` == 原 score（`ExpectScore`），`ZADD key XX score m`；新 member → `ZSCORE` 为 nil，`ZADD key NX score m`；删除 → `ZSCORE` == 原 score，`ZREM`；改 member → 旧的 `ZSCORE` == 原 score、新的为 nil，`ZREM old` + `ZADD key NX score new`。`ZREM` 在前。score 用 `strconv.ParseFloat`，失败报 `score "x" is not a number`；命令里的 score 用 `strconv.FormatFloat(f, 'g', -1, 64)`。`rank` 列被改时报 `the rank column cannot be edited`。
  - 任何一格是 NULL（`Value.Null`）→ `ErrNull`。`Deleted` 行不看它的值。

- Produces:
  ```go
  type Caps struct{ KeepTTL bool }
  // CapsFor reads redis_version ("7.2.4", "5.0.14"); KeepTTL from 6.0. "" or unparsable → no caps.
  func CapsFor(version string) Caps
  // String plans SET of a whole string value (only when it was read in full).
  func String(key, old, value string, c Caps) Plan
  // Usage is what NewKey wants after the key for typ, for the prompt's label.
  func Usage(typ string) string
  // NewKey plans creating key of typ with args (as rcmd.Split cut the prompt's text).
  func NewKey(typ, key string, args []string) (Plan, error)
  // Types are the types NewKey makes, in the order the picker lists them.
  var Types = []string{"string", "hash", "list", "set", "zset", "stream"}
  ```
- 规则：
  - **List**：有改值或删除时先加检查 `LLEN key` == `tg.Len`，每一行再加 `LINDEX key i` == 原值（i 是 `index` 列的原值）。改值 → `LSET key i v`；删除 → `LSET key i <Tomb>`；所有 `LSET` 之后，有删除时发一条 `LREM key 0 <Tomb>`。新行：`index` 列只能是 `head` 或 `tail`（新行默认 `tail`，由 keyTab 填），否则报 `new elements go to "head" or "tail"`；`head` 的新元素按表里从上到下的顺序最终排在最前面（一条 `LPUSH key` 参数倒序），`tail` 的按顺序一条 `RPUSH key`。推入命令排在 `LREM` 之后。改已有行的 `index` 列 → `the index column cannot be edited`。`Tomb` 为空时报错（调用方的 bug）。
  - **Stream**：已有条目只能删除，改了任何格 → `stream entries cannot be changed · delete one and add a new one`；删除 → 检查 `XRANGE key id id` 有 1 个元素（`ExpectLen 1`），`XDEL key id`；新行：`id` 列默认 `*`（keyTab 填），`fields` 列按 `rcmd.Split` 切开，必须是非空的偶数个，否则 `fields need name value pairs, e.g. name "Alice" age 3`；命令 `XADD key <id> f v …`。`XDEL` 在 `XADD` 之前。
  - **String**：检查 `GET key` == old；`KeepTTL` 时命令 `SET key value KEEPTTL`，否则 `SET key value` 且 `RestoreTTL = true`。
  - **NewKey**：检查 `EXISTS key` == 0（`What: key already exists`）。`string`：恰好 1 个参数，`SET key v`；`hash`：非空偶数个，`HSET key f v …`；`list`：至少 1 个，`RPUSH key e …`；`set`：至少 1 个，`SADD key m …`；`zset`：非空偶数个、奇数位是数字，`ZADD key s m …`；`stream`：非空偶数个，`XADD key * f v …`。参数不对时报 `expected <Usage(typ)>`。`Usage`：string `value`、hash `field value [field value …]`、list `element [element …]`、set `member [member …]`、zset `score member [score member …]`、stream `field value [field value …]`。

**Files:**

**Interfaces:**

- Produces（加进 `rdb.Client`）：
  ```go
  // Apply runs p on a dedicated connection: WATCH p.Key, the checks (one pipeline), MULTI, p.Cmds, EXEC.
  // A check that does not hold or fails, or an aborted EXEC, is *ChangedError and nothing is written.
  // A command failing inside EXEC is *ExecError.
  Apply(ctx context.Context, p redit.Plan) error
  // Expire sets the TTL (ttl < 0: PERSIST); false when the key is gone.
  Expire(ctx context.Context, key string, ttl time.Duration) (bool, error)
  // Rename is RENAMENX, or RENAME when overwrite; false when to exists and !overwrite.
  // A missing from is the server's error ("ERR no such key").
  Rename(ctx context.Context, from, to string, overwrite bool) (bool, error)
  Unlink(ctx context.Context, keys ...string) (int64, error)
  // ScanKeys is one SCAN without the TYPE lookups.
  ScanKeys(ctx context.Context, cursor uint64, match string, count int64) ([]string, uint64, error)
  ```
  ```go
  type ChangedError struct{ What string }
  func (e *ChangedError) Error() string // "key changed since loaded; refresh and retry" [+ " · " + What]
  type ExecError struct{ Index, Total int; Err error } // Index from 0
  func (e *ExecError) Error() string    // "command 2 of 3 failed: WRONGTYPE … · the others were applied"
  func (e *ExecError) Unwrap() error
  // applyHook runs between the checks and MULTI; tests set it.
  var applyHook func()
  ```
- 实现用 go-redis 的 `rc.Watch(ctx, fn, key)`：`fn` 里用 `tx.Pipelined` 发检查（`Do(ctx, args...)`，取 `cmd.Val()` / `cmd.Err()`；`redis.Nil` 当成 nil 回复传给 `Holds`），`RestoreTTL` 时同一个 pipeline 里多发一个 `PTTL`；然后 `applyHook`；然后 `tx.TxPipelined` 发 `Cmds`（`RestoreTTL` 且 PTTL > 0 时在 `SET` 后追加 `PEXPIRE key ms`）。`redis.TxFailedErr` → `&ChangedError{}`。`TxPipelined` 返回的各条命令里第一个出错的 → `ExecError`（`Total` 是实际发出的命令数）。其余错误走 `wrap`。

  ```go
  const ( bulkPreview = 20; bulkUnlink = 500 )
  type bulkPhase int
  const ( bulkCounting bulkPhase = iota; bulkConfirming; bulkDeleting )
  // bulkDelete is the one running pattern delete (one at a time per Model).
  type bulkDelete struct {
      key      redisDBKey
      pattern  string
      phase    bulkPhase
      cursor   uint64
      scanned  int64
      matched  int64    // counting: keys that matched
      sample   []string // the first bulkPreview matches, raw
      deleted  int64
      total    int64    // DBSIZE when it started
      gen      int
      cancel   context.CancelFunc
  }
  type bulkStepMsg struct{ gen int; keys []string; cursor uint64; scanned int64; deleted int64; err error }

  func bulkPattern(n *tree.Node, filter string) string // folder: GlobEscape(prefix)+"*"; db: its filter, else "*"
  ```
- 流程：
  1. 入口：只读 → `readOnlyHint`；已有批量删除在跑 → `a bulk delete is running · <Cancel 键> stops it`；这个 db 上有标签页带暂存修改 → 现有的 `canChange` 提示。
  2. **计数**：每批 `ScanKeys(cursor, pattern, 1000)`，累计 `matched`、留前 20 个；prod 上每批之间停 `prodScanPause`。状态栏 `counting keys matching <pattern> · scanned N / total · M found` 每批更新。`Cancel` 停止并提示 `stopped`。
  3. **确认**：0 个匹配 → `no keys match <pattern>`，结束。否则 `overlay.NewConfirm("Delete keys", lines, expect, …)`：第一行 `Delete N keys matching <pattern> in <conn>/db<K>?`，然后最多 20 个转义后的 key（多于 20 个时加 `… and N more`），然后 `Keys written while deleting may be missed.` 和 `This cannot be undone.`；`expect` 非 prod 为空，prod 为连接名。
  4. **删除**：从游标 0 重新 `ScanKeys`，每批匹配到的 key 按 500 个一组 `Unlink`，累加返回值；prod 每批之间停 `prodScanPause`；状态 `deleting keys matching <pattern> · N deleted`。`Cancel` 停止：`stopped · deleted N keys`。完成：`deleted N keys`。结束（完成、停止或出错）后对这个 db 调 `refreshKeys`（重新扫描、更新 DBSIZE）。
