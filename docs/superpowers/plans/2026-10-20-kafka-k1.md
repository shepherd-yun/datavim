# Kafka K1（排查与日常操作）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 sqlvim 里连上 Kafka（无认证 / SASL PLAIN / SCRAM，TLS / mTLS，可走 SSH 隧道）；树里浏览 broker、topic、consumer group（按 lag 排序）；Topic 标签页看消息、partition、配置、消费者；Group 标签页看 lag 和成员，`gd` 跳到卡住的消息；重置 offset、发消息、建删 topic；集群状态页。浏览对集群零副作用。

**Architecture:** 新建 `internal/kafka`（franz-go 的 `kgo` + `kadm` 封装，地位相当于 `internal/rdb`）和纯包 `internal/kmsgx`（起始位置、过滤、producer 草稿、重置 offset 计划、写操作分级）。`session.Manager` 缓存每个连接一个 `kafka.Client`，并用一个包装类型统一拦截所有写方法（只读检查的唯一检查点）；浏览消息用每个标签页独立的 `kafka.Reader`，它不持有 group。UI 增加 Kafka 树节点、Topic 标签页、Group 标签页、producer console 和 Kafka 状态页，按键全部进 keymap。

**Tech Stack:** Go 1.26、`github.com/twmb/franz-go`（`pkg/kgo`、`pkg/kadm`、`pkg/kfake`、`pkg/sasl/plain`、`pkg/sasl/scram`）、`github.com/testcontainers/testcontainers-go/modules/kafka` 和 `modules/redpanda`（和现有 testcontainers 同版本）。

**Spec:** `docs/superpowers/specs/2026-10-20-kafka-design.md`（本计划覆盖 K1：§3、§4（不含 Schema Registry 节点）、§5、§6、§8）

## Global Constraints

- 驱动名 `kafka`，默认端口 `9092`。`host` 是逗号分隔的 broker 列表，每项可带端口。`database` 不用。
- K1 的 `params`：`sasl`（`plain` / `scram-sha-256` / `scram-sha-512`，空表示不用 SASL）、`tls`、`tls_skip_verify`、`tls_ca`、`tls_cert`、`tls_key`、`client_id`（默认 `sqlvim`）、`show_internal`。`oauth`、`aws-msk-iam` 在 K1 里报错 `connection "x": kafka sasl "oauth" is not supported yet (want plain, scram-sha-256 or scram-sha-512)`。
- 支持 Apache Kafka 2.8 到 4.x、Confluent、MSK、Redpanda；按 ApiVersions 判断能力，不支持的功能只禁用这一项并显示 `not supported by this cluster`。
- **零副作用浏览**：`kafka.Reader` 只用 `kgo.ConsumePartitions` + `kgo.ConsumeResetOffset(kgo.NoResetOffset())`，不设置 group；任何客户端都不开 `kgo.AllowAutoTopicCreation`。
- key、value、header 一律 `[]byte` 原样保存；解码只在显示时做。
- 默认值（spec §5）：每次加载 200 条（每个 partition 最多 200 条再合并）；一个 Messages 视图最多保留 10,000 条；单条 value 超过 1,048,576 字节只保留前 1 MB 并提示 `showing first 1 MB of N`；跳转后前面带 3 条上下文；向后查找最多扫描 100,000 条；Group 的 Lag 每 5 秒刷新；状态页每 10 秒刷新；树上 lag 按每批 100 个 group 计算。
- 安全（spec §8.2）：只读连接拒绝所有写和危险操作，提示和 SQL 一致（`readOnlyHint`）；prod 写操作按 `y` 确认；prod 重置 offset 输入 group 名；删 topic 任何连接都输入 topic 名；非 prod 发消息不确认，其他写操作按 `y`。
- 重置 offset 只在 group 为 Empty 时允许；提交前重新读状态和 committed，与预览不一致就放弃，提示 `group changed since preview; review again`。
- UI 文字用英文；按键名一律用 `keyHint`；新按键进 `keymap/defaults.go` 并带描述；能和 SQL / Redis 共用的动作用同一个 Action 和默认键（spec §6 的表）。
- 密码、token 不写日志、不显示。
- 提交信息用 Conventional Commits 带 scope，**不加 Co-Authored-By**。用户能看到的改动在 Task 24 统一写进 `CHANGELOG.md` 的 `[Unreleased]`。

## Review Focus

1. **offset 已被 retention 删除**：跳到 `p1:120` 而 start 是 1,002,113 时，提示 `offset 120 is gone; earliest is 1,002,113`，不悄悄换位置，也不发起读取。测试在 Task 3（`Ranges` 返回 `ErrOffsetGone`）和 Task 15（UI 显示）。
2. **压缩 topic 和事务标记造成的 offset 空洞**：`Range` 读 [From, To) 时某些 offset 不存在，不能一直等待或者报错，读到 ≥ To 或 partition 末尾就结束。测试在 Task 9（kfake 里跳过的 offset）。
3. **group 从来没提交过某个 partition**：Lag 里 committed 显示 `-`，`gd` 定位到 partition 开头，重置目标 `next` 报错让用户选别的目标。测试在 Task 6 和 Task 18。
4. **二进制 key / value 和非 UTF-8 header**：表格预览不乱码（`\xNN`），`auto` 显示为 hex，复制 JSON 时 value 用 base64 并带 `value_encoding`。测试在 Task 2 和 Task 15。
5. **标签页关闭或切走时 live tail 仍在读**：关闭 Topic 标签页必须关掉它的 `Reader`；切到别的标签页时停止 `Poll`。测试在 Task 17。

### Task 5: `kmsgx`：producer 草稿格式

**Files:**
- Create: `internal/kmsgx/draft.go`
- Test: `internal/kmsgx/draft_test.go`

**Interfaces:**
- Produces:
  ```go
  type DraftRecord struct {
      Line, EndLine      int   // 这条消息在草稿里的起止行（从 1 开始，含）
      Key, Value         []byte
      KeyNull, ValueNull bool
      Partition          int32 // -1 表示按 key 分配
      Headers            []kafka.Header
  }
  type DraftError struct{ Line int; Msg string } // Error(): "line 3: <msg>"
  func ParseDraft(text string) ([]DraftRecord, error)       // 任何一条有错就返回 DraftError，不返回部分结果
  func DraftAt(text string, line int) (DraftRecord, error)  // 光标所在行属于的那一条
  ```
- 语法（spec §5.9）：消息之间用单独一行 `===` 分隔。每条开头连续的 `#` 行忽略；之后如果第一行匹配 `key:`、`partition:`、`header:` 就进入头部，头部到第一个空行结束；否则整段是正文。没有 `key:` 行 → `KeyNull`；`key: null` → `KeyNull`；`key:` 后面为空 → 空 key（非 null）。正文去掉末尾的空行；正文正好是 `null` → `ValueNull`；只有头部没有正文 → 空 value。`header: k=v`（`=` 必须有，值可以为空，名字不能为空，允许重复名字并保持顺序）。`partition:` 必须是 ≥ 0 的整数。重复的 `key:` / `partition:` 行报错。只有注释和空行的段落忽略。

- [ ] **Step 1: 写失败的测试**（表驱动）：spec §5.9 的示例 → 两条：第一条 key `ord-1`、partition 2、两个 header、value `{"id": 1, "amount": 99}`、`Line 2`；第二条 key `ord-2`、partition -1。没有头部的段落 `{"a":1}` → KeyNull、value 原样。`key: null` + 正文 `null` → KeyNull 且 ValueNull。`key:` 空 → Key 为空切片且 `!KeyNull`。错误：`partition: x`（`line 2: partition must be a number ≥ 0`）、`header: novalue`（`line 3: header needs name=value`）、两个 `key:`。`DraftAt` 光标在第二条正文行时返回第二条。正文里含 `key: x` 的行（在空行之后）属于正文。
