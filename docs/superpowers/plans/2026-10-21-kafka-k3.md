# Kafka K3（治理）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 在 K2 基础上完成 Kafka 系列的最后一期：ACL 的浏览、新建和删除；Kafka Connect（一个连接可以配多个 Connect 集群）的 connector 和 task 状态、暂停 / 继续 / 重启、查看和修改配置；按规则给消息内容打码（显示、复制、导出都打码）；SQL、Redis、Kafka 三种连接的写操作审计和查看页。

**Architecture:** 四项互不依赖，按 A（审计）→ B（ACL）→ C（Connect）→ D（打码）的顺序做，每组做完都可以单独发布。审计放在 `session`：和 §8.3 的只读检查点同一层，Kafka 的 `guardedKafka` / `guardedRegistry` / 新的 `guardedConnect` 在写方法返回后记一条，SQL 和 Redis 新增包装类型 `auditedConn` / `auditedSession` / `auditedRedis` / `auditedRedisSession`，按 `sqlx` / `rcmd` 的分级只记写语句；记录通过 `Manager.Audit` 回调写进 `history` 的新表 `audit`。ACL 是 `kafka.Client` 的 3 个新方法（kadm）。Connect 是新的 `kafka.Connect` 接口（REST，HTTP 走 `Config.Dial`）。打码是 `kmsgx` 的纯函数 `Masker`，UI 在消息进入 `msgView` 时就换成打码后的记录，之后的所有出口（表格、详情、复制、导出、`$EDITOR`、过滤）只见得到打码后的字节。

**Tech Stack:** Go 1.26、`github.com/twmb/franz-go/pkg/kadm`（已有，ACL：`DescribeACLs` / `CreateACLs` / `DeleteACLs` 和 `kadm.ACLBuilder`）、`kfake`（已有）、`net/http` + `net/http/httptest`（Connect，无新依赖）、testcontainers（已有）。**实现前用 Context7（`/twmb/franz-go`）确认 `kadm.ACLBuilder` 的方法名**（`Allow` / `Deny` / `Topics` / `Groups` / `Clusters` / `TransactionalIDs` / `ResourcePatternType` / `Operations` / `AllowHosts` / `DenyHosts`、`DescribeACLs` 的结果类型、`DeleteACLs` 的过滤语义），以及 Kafka Connect REST API 的 `expand`、`restart?includeTasks=&onlyFailed=` 参数（Connect 3.0+），本计划只规定 datavim 自己的接口。

**Spec:** `docs/superpowers/specs/2026-10-20-kafka-design.md`（本计划覆盖 K3：§9，以及 §8 对 K3 操作的扩展）。前两期：`docs/superpowers/plans/2026-10-20-kafka-k1.md`、`docs/superpowers/plans/2026-10-21-kafka-k2.md`。

## 作者在计划阶段的决定（spec §9 留到这里定的）

- **审计覆盖 SQL、Redis、Kafka 三种连接**的写和危险操作，一个查看页统一浏览。
- **一个 Kafka 连接可以配多个 Connect 集群**：`params.connect_url = "main=http://c1:8083, cdc=https://c2:8083"`；只写一个 URL（没有 `name=`）时，集群名是 `connect`。

## Global Constraints

- 只读连接拒绝所有写和危险操作（含新增的 ACL、Connect 写操作），提示是现有的 `readOnlyHint` / `session.ErrReadOnly`；检查只在 `session` 的包装类型里做（spec §8.3），反射测试要在接口新增写方法却没加检查（以及没加审计）时失败。
- K3 操作分级（追加进 spec §8.1 的表）：**写** = 新建 ACL、暂停 / 继续 connector、重启 connector 或 task、修改 connector 配置；**危险** = 删除 ACL。确认规则不变（spec §8.2）：危险操作输入对象名（ACL 是 principal，比如 `User:alice`）；prod 写操作按 `y`；非 prod 写操作也按 `y`（只有发消息在非 prod 免确认）。
- 删除 ACL 必须**正好删掉选中的那几条**：按每条 ACL 的全部字段精确匹配（pattern 类型用 literal / prefixed 本身，不用 `MATCH` / `ANY`），返回实际删掉的列表；删掉的多于选中的（服务器语义不同）时报错并在界面上列出多删的条目。
- Connect：所有 HTTP 请求走 `Config.Dial`（SSH 隧道）；`connect_user` 的密码是钥匙串账户 `<连接名>#connect`（环境变量 `DATAVIM_PASSWORD_<名字>_CONNECT`），第一次需要时询问，401 / 403 时重新询问，URL 里写了密码时不询问；URL 的 userinfo 不出现在错误、状态栏、日志里。修改配置前重新读配置，和打开时不一样就放弃：`connector config changed since you opened it; review again`。
- Connect 配置里名字匹配 `(?i)(password|secret|token|credentials|jaas|key$)` 的值显示成 `******`（标签页和 `$EDITOR` 里都是）；提交时仍是 `******` 的值换回原值，**不能把 `******` 写回 Connect**。
- 打码：只影响显示，不改变集群上的消息；表格、`K` 详情、`v` 的每种格式（含 hex / base64）、`yy` / `yl`、导出（所有格式，含 JSONL）、`<Space>v` 打开的临时文件、过滤匹配，都只用打码后的记录。打码后的值是 JSON 字符串 `"******"`。规则作用的部分不是 JSON（或者是还没解码完 / 解码失败的线格式）时，整个部分显示 `******`（失败时关闭，不漏）。有字段被打码的消息不能复制到 producer console 重发。
- 审计：每次**到达服务器**的写尝试记一条（成功或失败都记，`Err` 是错误文字；被只读拦截、在确认框取消的不记）；记录不包含消息内容、Redis 写入的值以外的东西由各节规定；写审计失败只 `slog.Warn`，**不影响操作本身的结果**；`audit` 表最多保留 `50,000` 条（包变量 `maxAudit`，测试里可以调小），最旧的先删。SQL 文本先过 `sqlx.RedactSQL`，Redis 命令先过 `rcmd.Redact`，两者都截到 2,000 个字符（常量 `auditDetailMax = 2000`，末尾加 `…`）。
- 密码、token、Connect / Schema Registry 凭据不写日志、不显示、不进审计。
- UI 文字用英文；按键名一律用 `keyHint`；新按键进 `keymap/defaults.go` 并带描述；能共用的动作用同一个 Action（spec §6）。
- 提交信息用 Conventional Commits 带 scope（英文），**不加 Co-Authored-By**。用户能看到的改动在每组的最后一个任务里写进 `CHANGELOG.md` 的 `[Unreleased]`（这样每组都能单独发布）。

## Review Focus

1. **删 ACL 删多了**：同一个 principal 在 `topic:orders` 上有一条 literal 和一条 prefixed 的 ACL，或者另有一条 `User:*` 的；删其中一条后另外两条还在。测试在 Task 7（kfake 支持 ACL 请求时用 kfake，否则用集成测试，Task 7 Step 1 说明）。
2. **打码从别的出口漏出来**：一条 `value.customer.phone` 被打码的消息，在 `v` 切到 hex / base64、`yl` 复制 VALUE、导出 JSONL、`<Space>v`、`fs 555` 过滤、live tail 新到的消息、线格式消息解码完成之前，都不能出现原始号码。测试在 Task 16（一个表驱动测试遍历每个出口）。
3. **Connect 配置往返**：`connection.password` 显示成 `******`，用户在 `$EDITOR` 里只改了 `tasks.max`；提交给 Connect 的 `connection.password` 必须是原值，确认框只列出 `tasks.max`。测试在 Task 13。
4. **审计拖垮或吞掉操作**：`audit` 表写失败（只读文件系统、SQLite 被锁）时，`UPDATE` / 删 topic 照常返回自己的结果；写失败的操作（权限不足）也记一条带 `Err` 的。测试在 Task 3 和 Task 4。
5. **Connect 凭据和隧道**：`connect_url = "main=https://u:p@c1:8083"` 返回 401 或连不上时，错误、状态栏、日志、审计里不能出现 `p`；配了 `ssh` 时 HTTP 请求用注入的 `Dial`。测试在 Task 10。

  ```go
  // (config.toml [[mask]]).
  type MaskRule struct {
      Connections []string `toml:"connections"` // connection names
      Env         string   `toml:"env"`         // or every connection of this env ("prod")
      Topics      []string `toml:"topics"`      // path.Match globs; empty: every topic
      Fields      []string `toml:"fields"`      // "key", "value", "key.<path>", "value.<path>"

  }

  ```

  ```go
  func NewMasker(rules []config.MaskRule, conn, env, topic string) *Masker

  func (m *Masker) Mask(r kafka.Record, key, value []byte) (out kafka.Record, masked bool)
  ```
