# Redis R2（命令控制台）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Redis 连接上打开一个像 redis-cli 的控制台：一行一条命令，vim 编辑，按行 / 选中 / 全部 / 从当前行执行；结果按 RESP3 结构显示成值、表格或缩进文本；`SELECT`、`MULTI` 在专用连接上持续有效；命令有补全和高亮；只读、prod、危险命令、`KEYS` 的安全规则在客户端生效。

**Architecture:** `rcmd`（纯包）负责命令行切分、内置命令表（从 Redis 7.4 的 `COMMAND INFO` / `COMMAND DOCS` 生成）、命令分级和守卫、事务状态、补全上下文。`rdb` 增加 `Session`：一条独立的专用连接（单独的 go-redis 客户端，`PoolSize 1`、不设读超时，取消靠 `ctx`），`Do` 返回结构化的 `Reply`。`session.Manager.RedisSession` 复用 R1 的密码 / 隧道 / TLS 逻辑打开它。UI 新增 `redisConsoleTab`，不改 SQL 的 `consoleTab`；它复用 `panes/editor`、`panes/grid`、`panes/textview`、`panes/complete`、草稿和历史。

**Tech Stack:** Go 1.26、`github.com/redis/go-redis/v9` v9.23.0（已在 go.mod）、testcontainers `modules/redis` v0.44.0。

**Spec:** `docs/superpowers/specs/2026-10-16-redis-design.md`（本计划覆盖 §5 和 §7；§3.3 的 `Session`、`Do` 也在这里实现）

## Global Constraints

- 一行一条命令，不需要 `;`。空行、以 `#` 或 `//` 开头的行（去掉前导空白后）忽略。
- 切分规则和 redis-cli 一致：空白分隔；`"…"` 里支持 `\n \r \t \b \a \" \\ \xNN`；`'…'` 里只有 `\'` 是转义；闭合引号后必须紧跟空白或行尾。引号没闭合时报错 `unterminated quote at col N`（N 从 1 开始，按字符数）。
- key 名、参数、值一律原样传递（Go `string` 当字节串）。显示时用 `rcmd.Escape`，复制 / 打开 key 时用原始字节。
- 不支持的命令（spec §5.5）：`SUBSCRIBE`、`PSUBSCRIBE`、`SSUBSCRIBE`、`MONITOR`、`SYNC`、`PSYNC`、`CLIENT TRACKING`、`RESET`、`HELLO`，以及本计划加的 `QUIT`、`CLIENT REPLY`（会让连接和客户端不同步）。提示 `<命令> is not supported in datavim`，不发给服务器。
- 安全规则（spec §7.2）：只读连接上写 / 危险 / 未知命令拒绝，提示里有 `:set noreadonly`；prod 上写命令和未知命令按 `y` 确认；任何连接上危险命令（除 `KEYS`）要确认，prod 上要输入连接名；`KEYS` 在 `DBSIZE > 10000` 时拒绝并提示改用 `SCAN` 或树过滤，否则按危险命令确认；多行一起执行时先检查全部，任何一条被拒绝就一条都不执行，需要确认的合并成一个确认框。
- `MULTI` 里不允许 `SELECT`（本计划的决定）：拒绝并提示 `SELECT inside MULTI is not supported · run it before MULTI`。这样 `EXEC` 之后的 db 编号不会和界面不一致。
- 事务中（`MULTI` 已开始）**不发 `PING`**（会被排队），也不自动重连。连接在事务或 `WATCH` 中断开时：提示事务丢失，状态回到非事务，不重连；下一次执行才重新连接。不在事务中断开时：自动重连并 `SELECT` 回原来的 db，消息里写 `reconnected (db N)`。
- 结果显示行数受 `settings.MaxRows` 限制，超出时标题写 `truncated`。
- `KEYS` 阈值、补全的后台 SCAN 上限用常量（`rcmd.KeysLimit = 10000`；补全扫描最多 5 批、每批 `COUNT 1000`、找到 50 个就停），不进 `config.toml`。
- R2 不支持 `:e` / `:w` 打开、保存文件，`:commit` / `:rollback`，和 `<Space>t` 手动事务；在 Redis 控制台上分别提示 `not supported for redis yet` 和 `redis transactions: use MULTI … EXEC / DISCARD`。
- UI 文字用英文；按键名一律用 `keyHint` 生成；新按键放进 `keymap/defaults.go` 并带描述。能和 SQL 共用的动作用同一个 Action 和同一个键。
- 不记录、不显示密码。`AUTH` 命令写进历史和消息时，参数替换成 `***`（`rcmd.Redact`）。
- 提交信息用 Conventional Commits 并带 scope，**不加 Co-Authored-By**。CHANGELOG 在 Task 12 统一写。

## Review Focus

1. **`MULTI` 里的 `PING`**：在事务中执行下一条命令前不能先 `PING` 探活，否则 `EXEC` 的结果会多出一个 `PONG`、排队数也错。测试在 Task 9（`TestRedisConsoleNoPingInMulti`）。
2. **`MULTI` 绕过守卫**：只读连接上 `MULTI` / `SET a 1` / `EXEC` 三行一起执行时整批拒绝；分三次执行时第二次被拒绝，`MULTI` 已经打开的事务仍然在（可以 `DISCARD`）。测试在 Task 3 和 Task 8。
3. **取消阻塞命令**：`BLPOP q 0` 时按取消，连接被 go-redis 关闭；如果之前 `SELECT 3`，下一条命令要先重连并回到 db3，消息里写 `reconnected (db 3)`，标题仍是 `dbN` 里的 3。测试在 Task 4（集成）和 Task 9（UI）。
4. **读超时误判断线**：`BLPOP q 5` 要等满 5 秒得到 `(nil)`，不能在 go-redis 默认的 3 秒读超时上报 `connection lost`。测试在 Task 4。
5. **结果里的二进制 key**：`SCAN 0` 返回 `"\xff"`，表格显示 `\xFF`，在这个单元格上打开 key 时 `KeyInfo` 收到的是原始 `"\xff"`。测试在 Task 10。

### Task 1: `rcmd`：命令行切分和按行拆分

**Files:**
- Create: `internal/rcmd/split.go`
- Test: `internal/rcmd/split_test.go`

**Interfaces:**
- Produces:
  ```go
  // Line 是控制台里的一条命令。Start/End 是这一行在整段文字里的字节偏移（不含换行）。
  type Line struct {
      Text       string
      Start, End int
      Num        int // 行号，从 1 开始
  }
  // Lines 把文字拆成命令行：跳过空行和注释行（# 或 //）。
  func Lines(text string) []Line
  // At 返回 offset 所在的那一行；offset 在空行或注释行上时 ok 为 false。
  func At(lines []Line, offset int) (Line, bool)
  // From 返回 offset 所在行及之后的所有行（offset 在空行上时从下一条开始）。
  func From(lines []Line, offset int) []Line
  // Within 返回和 [from, to) 有交集的行（VISUAL 选区按整行算）。
  func Within(lines []Line, from, to int) []Line
  // Split 按 redis-cli 规则把一行切成参数。
  func Split(line string) ([]string, error)
  // SplitError 是 Split 的错误；Col 是出错位置（字符，从 1 开始）。
  type SplitError struct{ Col int; Msg string }
  // Tokens 是宽松切分：引号没闭合时把剩下的部分当成最后一个参数（Open 为 true），用于补全和高亮。
  type Token struct{ Text string; Start, End int; Quoted, Open bool } // Start/End 是行内字节偏移
  func Tokens(line string) []Token
  // GlobEscape 转义 SCAN MATCH 里的 * ? [ ] \，用于"按前缀补全"。
  func GlobEscape(s string) string
  // Redact 返回用于显示 / 历史的一行：AUTH 的参数换成 ***（AUTH pw → AUTH ***；AUTH user pw → AUTH user ***），HELLO … AUTH u p 同理。
  func Redact(args []string) string
  ```

### Task 2: `rcmd`：内置命令表

**Files:**
- Create: `internal/rcmd/gen/main.go`（`//go:build ignore`）、`internal/rcmd/commands_gen.go`（生成的数据）、`internal/rcmd/commands.go`（类型和查找）
- Test: `internal/rcmd/commands_test.go`

**Interfaces:**
- Produces:
  ```go
  type Command struct {
      Name     string   // 大写；子命令是 "CONFIG SET" 这种形式
      Args     string   // 参数提示，比如 "key field value [field value ...]"
      Summary  string
      Group    string   // "string"、"hash"、"server" …
      Flags    []string // COMMAND INFO 的 flags：write、readonly、admin、blocking、noscript …
      ACL      []string // ACL 分类，不带 @：dangerous、keyspace …
      FirstKey, LastKey, Step int // COMMAND INFO 的 key 位置（相对命令名，子命令也从命令名算）；没有 key 时 FirstKey == 0
      Subcommands bool  // 有子命令的容器命令（CONFIG、CLIENT …）
  }
  // Lookup 按参数找命令：容器命令会继续看 args[1] 找子命令；大小写不敏感。
  // 找不到时 ok 为 false；容器命令后面的子命令不认识时返回容器本身，ok 为 false。
  func Lookup(args []string) (Command, bool)
  // Names 是所有顶层命令名（大写，排序），供补全。
  func Names() []string
  // SubNames 是容器命令的子命令名（不含容器名，大写，排序）。
  func SubNames(container string) []string
  // KeyArg 报告 args 里下标 i（0 是命令名）的参数是不是 key。
  func KeyArg(c Command, args []string, i int) bool
  // PairReply 报告这条命令在 RESP2 下返回的是成对数组：HGETALL、CONFIG GET、HRANDFIELD … WITHVALUES，
  // 以及带 WITHSCORES 的 ZRANGE / ZRANGEBYSCORE / ZREVRANGE / ZREVRANGEBYSCORE / ZRANDMEMBER / ZUNION / ZINTER / ZDIFF，
  // 和带 count 的 ZPOPMIN / ZPOPMAX。
  func PairReply(args []string) bool
  ```
- 生成器：`go run ./internal/rcmd/gen -addr localhost:6379 > internal/rcmd/commands_gen.go`，连一个 `redis:7.4` 容器，读 `COMMAND INFO`（flags、key 位置、ACL 分类、子命令）和 `COMMAND DOCS`（summary、group、arguments）。参数提示按 Redis 文档的写法渲染：可选用 `[…]`，可重复加 ` ...`，`oneof` 用 `a|b`，`token` 原样大写放在前面，`block` 用括号或方括号包起来。文件头写明 `// Code generated by internal/rcmd/gen from Redis 7.4.x; DO NOT EDIT.`，以及重新生成的命令。只收录服务器自带的命令（`COMMAND DOCS` 里 `module` 为空的）。
- `LastKey == -1` 表示到最后一个参数；`Step` 为 0 时按 1 算。`EVAL` / `EVALSHA` / `FCALL` 这类 `numkeys` 命令：`KeyArg` 对 `args[3 : 3+numkeys]` 返回 true（`COMMAND INFO` 的 key spec 不够用，写一个小的特例）。

- [ ] **Step 1: 生成数据**：`docker run -d --rm -p 6390:6379 redis:7.4`，写 `gen/main.go` 并运行，生成 `commands_gen.go`；`gofumpt` 后提交前检查文件里有 `HSET`、`CONFIG SET`、`CLIENT KILL`、`EVAL_RO`、`XADD`。
- [ ] **Step 2: 写失败的测试**（表驱动）：
  - `TestLookup`：`[hset k f v]` → `HSET`，`Args` 以 `key field value` 开头；`[config set maxmemory 1]` → `CONFIG SET`；`[CONFIG nope]` → `ok == false`、`Name == "CONFIG"`；`[nope]` → `ok == false`；`[json.get k]` → `ok == false`（模块命令不在表里）。
  - `TestKeyArg`：`HSET k f v` 下标 1 是 key、2 不是；`MSET a 1 b 2` 下标 1、3 是 key，2、4 不是；`DEL a b c` 下标 1~3 都是；`EVAL "return 1" 2 k1 k2 arg` 下标 3、4 是，5 不是；`GET` 只有命令名时下标 1 是 key（补全用）。
  - `TestPairReply`：`HGETALL k` true；`ZRANGE k 0 -1` false；`ZRANGE k 0 -1 withscores` true；`CONFIG GET *` true；`ZPOPMIN k` false、`ZPOPMIN k 2` true；`HRANDFIELD k 3 WITHVALUES` true。
  - `TestNames`：`Names()` 包含 `GET`、`SCAN`，不包含 `CONFIG SET`；`SubNames("CLIENT")` 包含 `KILL`、`LIST`。
- [ ] **Step 3: 运行** `go test -race ./internal/rcmd -run 'Lookup|KeyArg|PairReply|Names'`，预期 FAIL。
- [ ] **Step 4: 实现** `commands.go`。查找表在包初始化时从生成的切片建成 `map[string]*Command`。

### Task 3: `rcmd`：命令分级、守卫、事务状态

**Files:**
- Create: `internal/rcmd/guard.go`、`internal/rcmd/tx.go`
- Test: `internal/rcmd/guard_test.go`、`internal/rcmd/tx_test.go`

**Interfaces:**
- Consumes: Task 1 的 `Line`、`Split`；Task 2 的 `Lookup`、`Command`。
- Produces:
  ```go
  type Level int
  const ( Read Level = iota; Write; Dangerous; Unsupported; Unknown )
  func (l Level) String() string // "read"、"write"、"dangerous"、"unsupported"、"unknown"
  // Classify 给一条命令分级，name 是用于提示的名字（"CONFIG SET"、"FOO"）。
  func Classify(args []string) (level Level, name string)

  type Verdict int
  const ( Allow Verdict = iota; Reject; Confirm )
  type Policy struct {
      ReadOnly, Prod bool
      Conn   string // prod 上危险命令要输入的名字
      DBSize int64  // 批次里有 KEYS 时由调用方先查好；-1 表示没查
      InMulti bool  // 执行前事务已经开始（SELECT 检查用）
  }
  type Check struct {
      Verdict Verdict
      Line    int      // 触发检查的那一条在 lines 里的下标
      Reason  string
      Title   string
      Body    []string
      Expect  string   // Confirm：要输入的文字；空表示按 y
  }
  const KeysLimit = 10000
  // Guard 先检查整批，规则见 Global Constraints；切分出错的行按 Reject 返回（Reason 是切分错误）。
  func Guard(lines []Line, p Policy) Check
  // NeedsDBSize 报告这批里有 KEYS（调用方要先查 DBSIZE）。
  func NeedsDBSize(lines []Line) bool

  // TxState 跟着执行结果走事务状态。
  type TxState struct {
      InMulti  bool
      Watching bool
      Queued   int
  }
  // Apply 记录一条执行过的命令；failed 表示服务器回了错误。
  func (s *TxState) Apply(args []string, failed bool)
  func (s TxState) Active() bool  // InMulti || Watching
  func (s TxState) Badge() string // "TX 3"（MULTI 中，排队 3 条）、"WATCH"、""
  ```
- 分级规则（按顺序，第一条命中的为准）：
  1. 不支持表（Global Constraints）→ `Unsupported`。
  2. 显式覆盖表（必须正确的例子，spec §7.1）：读 `EVAL_RO`、`EVALSHA_RO`、`FCALL_RO`、`SELECT`、`PING`、`INFO`、`CONFIG GET`、`CLIENT LIST`、`CLIENT INFO`、`CLIENT GETNAME`、`CLIENT ID`、`SLOWLOG GET`、`SLOWLOG LEN`、`MEMORY USAGE`、`OBJECT ENCODING`、`MULTI`、`EXEC`、`DISCARD`、`WATCH`、`UNWATCH`、`AUTH`、`ECHO`、`TIME`、`DBSIZE`、`ROLE`、`LASTSAVE`、`COMMAND *`；写 `EVAL`、`EVALSHA`、`FCALL`、`SCRIPT LOAD`、`FUNCTION LOAD`；危险 `FLUSHDB`、`FLUSHALL`、`KEYS`、`CONFIG SET`、`CONFIG REWRITE`、`CONFIG RESETSTAT`、`SHUTDOWN`、`DEBUG`、`SCRIPT FLUSH`、`SCRIPT KILL`、`FUNCTION FLUSH`、`FUNCTION DELETE`、`FUNCTION RESTORE`、`FUNCTION KILL`、`CLIENT KILL`、`CLIENT PAUSE`、`CLIENT NO-EVICT`、`REPLICAOF`、`SLAVEOF`、`MIGRATE`、`ACL SETUSER`、`ACL DELUSER`、`ACL LOAD`、`ACL SAVE`、`SAVE`、`BGSAVE`、`BGREWRITEAOF`、`SWAPDB`、`MODULE LOAD`、`MODULE LOADEX`、`MODULE UNLOAD`、`FAILOVER`、`CLUSTER *`、`SLOWLOG RESET`、`LATENCY RESET`、`MEMORY PURGE`。
  3. `Lookup` 找不到 → `Unknown`（容器命令的子命令不认识也是 `Unknown`）。
  4. flags 有 `write` → `Write`。
  5. flags 有 `admin`，或 ACL 有 `dangerous` → `Dangerous`。
  6. 其余 → `Read`。
- 确认框文字：prod 写 / 未知合并成 `Title "Write to PROD"`，`Body` 第一行 `N command(s) will run on PROD cache:`，后面每条一行 `write: SET user:1 …`（用 `Redact`，超过 60 个字符截断）。危险命令 `Title "Dangerous command"`（prod 上加前缀 `PROD · `），`Body` 列出命令，prod 上 `Expect = Conn`。一批里同时有危险和 prod 写时，只弹危险那个框，Body 里列出全部。

- [ ] **Step 1: 写失败的测试**（表驱动）：
  - `TestClassify`：`GET`、`HGETALL`、`SCAN`、`TTL`、`TYPE`、`INFO`、`DBSIZE`、`EVAL_RO`、`FCALL_RO`、`SELECT`、`PING`、`CONFIG GET` → Read；`SET`、`DEL`、`UNLINK`、`HSET`、`EXPIRE`、`RENAME`、`EVAL`、`EVALSHA`、`FCALL` → Write；spec §7.1 危险列表里的每一个 → Dangerous；`SUBSCRIBE`、`MONITOR`、`HELLO`、`RESET`、`CLIENT TRACKING`、`QUIT` → Unsupported；`JSON.SET`、`FOO`、`CONFIG NOPE` → Unknown；大小写混合（`config Set`）结果一样，`name` 是 `CONFIG SET`。
  - `TestGuard`（每行一个用例，`Lines` 来自多行文字）：
    - 只读：`GET a` Allow；`SET a 1` Reject，Reason 含 `:set noreadonly`；`FOO` Reject；`FLUSHDB` Reject；`MULTI\nSET a 1\nEXEC` Reject 且 `Line == 1`；`GET a\nSET b 1` Reject（整批不执行）。

    - `KEYS *`：`DBSize 20000` → Reject，Reason 含 `SCAN`；`DBSize 50` → Confirm（危险）。
    - 不支持：`SUBSCRIBE ch` 在任何连接上 Reject，Reason `SUBSCRIBE is not supported in datavim`。

  ```go
  }
  ```
  `app.go` 和 `importrun.go` 里所有 `t.(*consoleTab); ok && c.openTx()` 的地方改成 `t.(txHolder)`（连接名用 `Target()` 的第一个返回值）。`redisConsoleTab.openTx()` 返回 `tx.Active()`，`TxStatus()` 返回 `tx.Badge()`。
- 行为：
  - 每条结果都 `tx.Apply(args, reply.Kind == KindError)`。`MULTI` 中排队的命令在消息日志里写 `… — QUEUED`。
