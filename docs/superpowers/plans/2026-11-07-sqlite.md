# SQLite 支持实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增 `sqlite` 驱动，能打开本地文件和 SSH 服务器上的文件，两者都能增删改查。

**Architecture:** `internal/db/sqlite` 上层（Dialect、DDLWriter、MetaReader、Conn、Session）只依赖一个内部 `engine` 接口；本地引擎用 `modernc.org/sqlite`，命令行引擎通过 `db.ExecFunc` 驱动服务器上的 `sqlite3` 进程。SSH 由 `tunnel.Pool.Exec` 实现，经 `session.Manager` 注入。

**Tech Stack:** Go、`modernc.org/sqlite`、`golang.org/x/crypto/ssh`、`sqlite3` CLI（`.mode quote`）、Bubble Tea v2。

**Spec:** `docs/superpowers/specs/2026-11-07-sqlite-design.md`。每个任务开始前都要读，文档里的实测结果和安全要求是本计划的依据。

## Global Constraints

- 文件只由和它同机的 SQLite 进程访问；禁止 SFTP 或“下载、修改、上传”。
- 不新建数据库文件：本地 `mode=rw`/`mode=ro`，远程 `file:<路径>?mode=rw|ro`。
- 只读、生产确认、无 WHERE 拦截、编辑只影响一行、事务中不静默重连必须保留。
- 服务器 `sqlite3` 最低 3.26，低于此版本明确报错。3.37 及以上的只读远程连接加 `-safe`。
- 所有远程连接拒绝点命令、`edit`、`load_extension`；只读远程连接再拒绝 `writefile`、`readfile`、`fsdir`、`ATTACH`。
- 不向服务器上传程序。发布构建保持 `CGO_ENABLED=0`。
- 依赖只能向下：`db` 不能导入 `tunnel` 或 `x/crypto/ssh`。
- UI 文案用英文，按键提示用 `keyHint`，比较能力用 `Features`，不比较驱动名。
- Conventional Commits 带 scope。不加 Co-Authored-By 或任何 Claude 署名。
- 用户可见的改动写入 `CHANGELOG.md` 的 `[Unreleased]`；README 改动同步到 `README.zh-CN.md`。

## Review Focus

1. 路径含空格、引号、中文、`?#%`，或以 `~/` 开头：能打开正确的文件，且不产生 shell 注入。（任务 3）
2. 数据库被线上应用锁住：等 5 秒后报 `database is locked`，Session 仍可用，不挂起。（任务 4）
3. 控制台输入只有注释、空白或多条语句，或字符串里有一行以 `.` 开头：只有注释和空白时不挂起也不报错，多条语句逐条执行，字符串里的 `.` 行照常发送。（任务 3、4）
4. 文本含非 UTF-8 字节、超长单行（10 MB）、内嵌 `\r\n`，或者内容恰好和标记形式相同：完整读回，不串帧。（任务 3、4）
5. `sqlite3` 在两条语句之间意外退出（服务器重启、OOM）：下一次调用返回 `ErrConnLost`，不挂起；事务中不重连。（任务 4）

- [ ] **Step 3: 实现单个进程 `cliproc`**

启动顺序：先用 `versionCommand` 读版本（`Conn` 只读一次，决定 `-safe`；低于 3.26 报错），再运行 `startCommand`，读 `PID=` 行，发送 `.mode quote`、`.headers on`、`.timeout 5000`、`PRAGMA foreign_keys=ON;`。

每条语句的发送顺序：

1. `checkStmt`，再 `bindArgs`；
2. 语句以 `SELECT`、`WITH`、`VALUES` 开头时，发送临时视图、`pragma_table_info` 和 `DROP VIEW`，各带标记；视图失败不算错误；
3. 语句 + `\n;\n`，再 `.print <标记>`；
4. 非行语句再发 `SELECT changes(), last_insert_rowid();` 和标记。

标记为每进程随机 128 位十六进制。写 stdin 放到单独的 goroutine，避免大语句和输出互相阻塞。事务状态用 `sqlx.TransactionEffect` 跟踪，有疑问时算作“事务中”。

- [ ] **Step 4: 实现取消和提前停止**

按设计：取消时通过新的 `Exec` 运行 `kill -INT <pid>`；事务外透明重启，事务中将 Session 标记为丢失。`ErrStop` 在 Session 上读完并丢弃（期间响应取消），在连接池进程上直接杀掉并替换。

读 stdout 遇到 EOF 就返回 `ErrConnLost` 包装的错误，并在消息里写明 `connection lost; the running statement may still finish on the server`，事务中再加 `uncommitted changes will not be kept`。

- [ ] **Step 5: 实现进程池**

最多 4 个进程，按需启动，空闲 60 秒关闭。`Session` 不占池内名额，但各自独占一个进程。OpenSSH `MaxSessions` 超限的错误原样向上传递，不重试。
